Can an AI agent do a Rails upgrade?

On the one app we measured, an automated pass did most of the edits, and fast. Left alone, it missed half of what was flagged as breaking. The first pass on a 27,000-line Rails app found four of eight flagged lines and shipped a stage that passed every check and didn't start with one feature switched on.

Last updated November 18, 2026

A

What the first pass did

The app is Postal, an open-source mail server on Rails 7.1.6, with 851 test examples. Nobody at the Postal project asked for this, and we aren't affiliated with the project. The target was Rails 8.1. The first pass was automated, with no separate review.

It found four lines that documented Rails changes would break. Three stages then went onto a fork, and each passed every check we had: the test suite, a comparison of 170 recorded HTTP responses, and the same checks again on GitHub Actions.

Then the work got a separate review pass. It found four more breaking lines, and one of them was already a defect in the third stage. With an optional start-up feature switched on, the app didn't start on Rails 7.2. The test suite loads that line and never executes it, so no check we had could see it.

B

What the review caught

A separate review pass is a fixed step in our work. Every Upgrade Roadmap and every stage gets one, and a stage isn't published until it passes. A Roadmap you pay for gets a person's review after that.

We also put the defective stage through that review as it stood, without being told what had been found. The review found the defect, and two more problems with the stage.

C

What it means if you try it

The automated pass produced a plan that read well and made most of the edits. It was half right, and three of the four misses were in code that no test runs. This is one app and one automated pass, tested in November 2026.

If an agent, a contractor or your own team does your upgrade, these are the questions we'd ask of the result.

  • Does the app start in every configuration production uses, after every step? A green test suite didn't show a process that wouldn't boot.
  • What checked the code that no test runs? That's where three of the four misses were.
  • What changed in behavior without failing anything? The 7.2 step moved a time zone by an hour, and no test failed.
  • Was it reviewed by something other than what wrote it?
